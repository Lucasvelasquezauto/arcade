## SUPUESTOs

1. **`main.ts` y no `main.tsx`.** El tsconfig compartido no declara la opción `jsx`
   (es de alcance de todo el monorepo, no de `apps/arcade`), y esta página no usa JSX
   — no hay shell en Preact todavía que consumir. Cuando el shell se integre, este
   archivo pasa a `.tsx` junto con el cambio de tsconfig, que hay que pedir al hilo
   orquestador porque toca un archivo compartido.
2. **`document` se accede con un cast local a `globalThis`**, como
   `packages/core/src/env.ts`, en vez de agregar la lib `dom` al tsconfig compartido:
   esa lib es global a todo el `tsc` del monorepo y filtraría tipos del DOM hacia la
   lógica pura de juego (Art. 3.1). Sigo el patrón que ya estableció `core` para este
   mismo problema.
3. **`registerType: 'prompt'`** en vite-plugin-pwa, no `'autoUpdate'`. `product-spec.md`
   §11.3 exige que una actualización de la app no interrumpa una partida en curso; con
   `'prompt'` y el registro automático por defecto (sin callback propio), un service
   worker nuevo se instala en segundo plano y solo toma control en la siguiente carga
   completa, nunca a mitad de partida. La UI de aviso de "hay una versión nueva" queda
   pendiente para cuando exista el shell.
4. **`orientation: 'portrait-primary'`** (no `'portrait'`) para "orientación vertical
   bloqueada": es el valor que efectivamente bloquea a una sola orientación en vez de
   permitir primary+secondary.
5. **Nombre de la app "ARCADE"** tomado literalmente de esta tarea, no de
   `product-spec.md` PEND-05 (que sigue sin resolver — "Nombre de la app y arte de la
   marquesina principal" bloquea la spec del shell). Si el propietario elige otro
   nombre para PEND-05, este manifiesto y el ícono hay que actualizarlos.
6. **Constitución y spec del esqueleto marcadas "pendiente de aprobación".** Procedí
   igual porque el hilo orquestador (este mismo mensaje) dio la instrucción directa y
   detallada de construir exactamente esto, y las ramas `m1-core-render`/`m1-shell` ya
   construyeron sobre esta misma spec sin que nadie la bloqueara por ese estado. Lo
   dejo señalado por si el propietario todavía no la considera vinculante.

### Discrepancia encontrada contra `docs/repo-structure.md` §5

`repo-structure.md` dice literalmente: *Install command: `pnpm install --frozen-lockfile`*.
La documentación actual de Vercel (`vercel.com/docs/package-managers`,
"Manually specifying a package manager") dice, citado:

> "When using an override install command like `pnpm install`, Vercel will use the
> oldest version of the specified package manager available in the build container.
> For example, if you specify `pnpm install` as your override install command, Vercel
> will use **pnpm 6**."

Este `pnpm-lock.yaml` es `lockfileVersion: '9.0'` (requiere pnpm 9 o 10). Si se escribe
a mano cualquier Install Command que empiece con `pnpm install` — con o sin
`--frozen-lockfile` — Vercel usa pnpm 6 para ejecutarlo, que no puede leer este
lockfile: el build se rompe. La detección automática de Vercel (sin override), en
cambio, sí lee `pnpm-lock.yaml`, detecta `lockfileVersion: 9.0` y usa pnpm 9 o 10
correctamente (`vercel.com/docs/package-managers`, tabla de detección). Además, Vercel
fija `CI=1` en el entorno de build, y pnpm activa `--frozen-lockfile` por defecto
cuando `CI` está presente — así que dejar el Install Command en automático consigue el
mismo efecto que pedía `repo-structure.md`, sin el riesgo de la versión equivocada de
pnpm.

**No toqué `repo-structure.md`** porque es de exclusividad del hilo orquestador (regla
de este mismo `CLAUDE.md`). Dejo esto señalado para que se corrija ahí o se confirme
que el Install Command debe quedar en automático.

**Alternativa más explícita, si se prefiere fijar la versión de pnpm sin depender de
detección automática:** habilitar Corepack (`ENABLE_EXPERIMENTAL_COREPACK=1` como
variable de entorno del proyecto) y agregar `"packageManager": "pnpm@11.25.0"` al
`package.json` raíz — eso sí requiere tocar un archivo fuera de `apps/arcade`, así que
lo dejo como sugerencia para el hilo orquestador, no lo hice yo.
